# EduPulse System Prototype

- **What:** KCP CIT BSIT capstone. AI-assisted syllabus, courseware and performance system for the College of Information Technology, King's College of the Philippines.
- **Stack:** React 19 + Vite front end (`edupulse-app/src`), Node API (`edupulse-app/server`), Vercel functions (`edupulse-app/api`), Supabase (auth, accounts per role), GSAP 3.15 and three.js 0.186 on the landing page, Playwright for browser tests and documentation captures.
- **Users:** five roles, one per account: System Admin, Dean, Associate Dean, Instructor, Student. EduSuite stays the system of record; AI output stays a draft until people approve it; Pulse never answers assessments; scores, not official grades.
- **Data:** Supabase in production; local JSON data under `edupulse-app/.data` for development and tests.
- **Constraints:** documentation and screenshots change in the same commit as any visible change (see `CLAUDE.md` at the repository root and `feature-documentation/DOCUMENTATION-POLICY.md`); release gate is `npm run verify` plus `npm run test:browser`; a push to `main` deploys to Vercel.
- **Public site:** home `/` is the 3D school walk (`components/landing/classroom/`; `mode.js` picks `full`, `lite` or `flat`, and `wantedMode()` reloads the page only when that mode really changes). Between Pulse and the agents the wall clock grows into the agents scope and then the agent workspace (`clockface.js`, `scope.js`, `AgentsSection.jsx`; the scope shows the workspace's own 3D agents). The bar lists Home and eight pages (`pages/public/*Page.jsx` on `components/public/RoomPage.jsx` + `room/themedRoom.js`): each is one themed room that never scrolls; tapping a label zooms to its prop and opens its card (Escape returns). Cats can be petted, carried and annoyed (`room/cat.js`); Play runs the games on the cabinets' screens with a robot at the keys (`gameRounds.js`, `games.jsx`); Pulse is the agent studio plus a scripted chat (`pulseTalk.js`); the round `RoomDial` lists the room's things; day/night is the app's `.dark-mode` (ThemeContext) and the 3D scenes follow it. Automated browsers (`navigator.webdriver`) get the flat home page, without the walk, unless localStorage `edupulse-walk` is `on`; 3D scenes are built after `landing/settle.js` (first touch or 20 s). A link to `#/?section=workspace` lands where the agents pin ends, with the room open (`navigation.js` `sectionTop`).
- **Egress and models:** `server/modelLifecycle.ts` hides retired provider models (update its list and its checked date when a provider announces a deprecation); the workspace GET takes `?known=<revision>` and answers `unchanged` from the revision column alone; the browser refreshes records about every 5 minutes and checks the workspace about every 2 minutes, with saves debounced at 1.5 s; `vercel.json` caches `/assets` (immutable) and `/ocr`; routes are lazy (`App.jsx`) and vendor chunks are split in `vite.config.js`.
- **Machine notes:** low free memory, so run browser tests with one worker; a dev server from another session can linger on a port (check `Get-NetTCPConnection` before trusting it); in Playwright, a `#/` navigation on the same URL does not reload the page, use `page.reload()`. Git Bash rewrites arguments that start with `/` into Windows paths (pass `features`, not `/features`); the repo's local `core.autocrlf` is false but the index is LF, so stage and diff with `git -c core.autocrlf=true`; the Token Optimizer plugin blocks reading PNGs, so review images on a localhost contact sheet with the Playwright MCP; an element screenshot taller than the window resizes it, and the landing page used to reload on that (fixed in `mode.js`). `tests/browser/baseline-workflows.spec.ts:53` (Pulse guidance, Dean marks read-only) fails on upstream `main` too: the performance page opens Pulse's general agent.
