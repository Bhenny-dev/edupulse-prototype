# EduPulse System Prototype

- **What:** KCP CIT BSIT capstone. AI-assisted syllabus, courseware and performance system for the College of Information Technology, King's College of the Philippines.
- **Stack:** React 19 + Vite front end (`edupulse-app/src`), Node API (`edupulse-app/server`), Vercel functions (`edupulse-app/api`), Supabase (auth, accounts per role), GSAP 3.15 and three.js 0.186 on the landing page, Playwright for browser tests and documentation captures.
- **Users:** five roles, one per account: System Admin, Dean, Associate Dean, Instructor, Student. EduSuite stays the system of record; AI output stays a draft until people approve it; Pulse never answers assessments; scores, not official grades.
- **Data:** Supabase in production; local JSON data under `edupulse-app/.data` for development and tests.
- **Constraints:** documentation/screenshot updates are PAUSED by the owner since 2026-11-14 (`paused` in `feature-documentation/doc-map.json`); normally they change in the same commit as any visible change (see `CLAUDE.md` at the repository root and `feature-documentation/DOCUMENTATION-POLICY.md`); release gate is `npm run verify` plus `npm run test:browser`; after a push to `main`, run `npm run deploy:production -- --check` then `npm run deploy:production` from `edupulse-app` and verify Ready (see `feature-documentation/backend-system/vercel.md`). The transferred Vercel project has no working Git link; a push alone does not deploy.
- **Core flow plan:** `feature-documentation/CORE-FLOW-WORKSPACE.md` holds the owner's Dean -> Instructor -> Student requirements (R-*), the audit and goals G1-G12; work them in order and update task stages and the log in the same commit. Production migrations go out with `npx supabase db push --linked` (CLI linked to `xyziepdkdvvuhgkymooo`), checked with `npx supabase migration list --linked`.
- **Courseware packs:** a folder of weekly PDFs (teaching material, assessment, instructor key, source register) becomes draft courseware. `scripts/lib/courseware-pack.ts` reads it (choice, true or false, matching, applied decision, criteria and practice-test parts; any other part is refused, so the WMADE 3 pack needs more reader work first) and `scripts/seed-courseware-pack.ts --pack <folder> --course "IT 204" --owner-email <staff email> --output .data/<dir> [--check-transaction | --apply]` adds only the weeks a course lacks to one instructor's workspace (read-only dry run by default). A written part worth several points becomes one question per marking point because each question is one mark. It refuses the Fianza-Buya and Guisdan accounts (the owner keeps their courses untouched for upload tests). PowerShell 5.1: read and write UTF-8 files with `[IO.File]::ReadAllText(path, UTF8)`; `Get-Content -Raw` plus `WriteAllText` double-encodes non-ASCII text.
- **Public site:** home `/` is the 3D school walk (`components/landing/classroom/`; `mode.js` picks `full`, `lite` or `flat`, and `wantedMode()` reloads the page only when that mode really changes). Between Pulse and the agents the wall clock grows into the agents scope and then the agent workspace (`clockface.js`, `scope.js`, `AgentsSection.jsx`; the scope shows the workspace's own 3D agents). The bar lists Home and eight pages (`pages/public/*Page.jsx` on `components/public/RoomPage.jsx` + `room/themedRoom.js`): each is one themed room that never scrolls; tapping a label zooms to its prop and opens its card (Escape returns). Cats can be petted, carried and annoyed (`room/cat.js`); Play runs the games on the cabinets' screens with a robot at the keys (`gameRounds.js`, `games.jsx`); Pulse is the agent studio plus a scripted chat (`pulseTalk.js`); the round `RoomDial` lists the room's things; day/night is the app's `.dark-mode` (ThemeContext) and the 3D scenes follow it. Automated browsers (`navigator.webdriver`) get the flat home page, without the walk, unless localStorage `edupulse-walk` is `on`; 3D scenes are built after `landing/settle.js` (first touch or 20 s). A link to `#/?section=workspace` lands where the agents pin ends, with the room open (`navigation.js` `sectionTop`).
- **Egress and models:** `server/modelLifecycle.ts` hides retired provider models (update its list and its checked date when a provider announces a deprecation); the workspace GET takes `?known=<revision>` and answers `unchanged` from the revision column alone; the browser refreshes records about every 5 minutes and checks the workspace about every 2 minutes, with saves debounced at 1.5 s; `vercel.json` caches `/assets` (immutable) and `/ocr`; routes are lazy (`App.jsx`) and vendor chunks are split in `vite.config.js`.
- **Uploaded files:** a teaching material or approved syllabus made from a file shows the file itself, never text read from it: PDF pages (pdf.js), Word (mammoth into a script-free frame) and PowerPoint slides (`utils/pptxSlides.ts` reads the .pptx into positioned boxes, `components/documents/SlidePages.jsx` draws them), shared in `components/documents/`, opened from `courseware/OriginalFile.jsx` (bytes via `teachingFileBytes` from the signed URL); anything else stays a download and the extracted text is the fallback. Compare slide drawings with the `docProps/thumbnail.jpeg` PowerPoint saves inside a deck.
- **Providers:** `server/connections.ts` (`providerNames`, discovery), `providers.ts` (chat endpoints; DeepSeek runs with thinking off and retries one blank JSON reply; Hermes is a Nous Portal key whose model list is public, so a new key is checked with a one-token request), `modelLifecycle.ts`, the CHECK on `edupulse_provider_connections.provider` (add a migration for a new one) and the cards in `ProviderConnection.jsx`. OpenRouter 402s are read by `error.metadata.limit_source` (`openRouterPaymentError`: key limit, balance below zero, in-flight budget, paid Whisper for voice, paid model); a free OpenRouter model (`isFreeOpenRouterModel`) never gets the paid `openrouter:web_search` tool, research uses the keyless search instead.
- **Pulse list edits:** `agents/requestFrame.ts` reads a message against the open editor's lists (`fieldIndex.ts`): command, "question 3", "last two", positions, counts, format, topic. `itemEdits.ts` removes, moves and swaps in code, and adds or rewrites through a strict positional contract; results carry `structural` so a selected field never narrows them. The three operator request gates (`toolPlanner.ts`, `lib/operatorClient.ts`, `server/http.ts`) all call `operatorFrame`, so "remove question 3" passes without educational-content wording. `server/systemIndex.ts` splits records into field, week and section passages for System Search.
- **Pulse account views:** `agents/operator.js` `accountRequest` reads "open / redirect me to / log in as the account or authenticated UI of <name>" (a role, a pronoun or a page name is not a person); `planOperator` makes it an `open-account` proposal for the verified System Admin (`canSwitchRoles`) and a notice for everyone else. `Pulse.jsx` `resolveAccount` searches the four account roles with `lib/accountSearch.ts` `findAccounts` (the `support` directory matches only a whole substring, so it retries with the longest words and 3-letter prefixes and ranks with `nameMatch`), opens a single match through `AuthContext` `openAccount` (the picker's `selectAccount` with an explicit role) and lists several, or the closest names, as `account-choices`.
- **Chat pictures:** `lib/aiClient.ts` `CHAT_UPLOAD_ACCEPT` (the library's `UPLOAD_ACCEPT` stays documents-only) and `isImageFile` send a picture from `readReferenceFile` to `lib/imageReference.ts`: its text is read by OCR on the device (`lib/ocr.ts` `ocrImage`: canvas scaled by `ocrText.ts` `imageScale`, one picture at a time through the same Tesseract assets as scanned PDFs), never uploaded; the attachment title ends "(OCR)" and carries `ocr.confidence`. A ruled picture (a teaching-load screenshot) is enlarged to about 3300 px, inked black on white paper (`ocrText.ts` `whiteBackground`/`inkOnWhite`), read as one block (PSM 6, rules painted out) and becomes `teachingLoad` through the PDF reader (`readTeachingLoadLayouts`: headings tolerate one OCR misread, a row with a course code counts even when its number was not read). The load review (`TeachingLoadImport.jsx`) names what each selected row still needs (registered instructor, recorded course, the selected term), counts each need in the footer and offers "Keep only ready rows". A subject missing from the recorded courses defaults to "Add … as a new course" (code without the section letter, printed title and units, code editable); Confirm runs `course.create` for each new course in the selected term before `load.import_document`.
- **Block sections:** a course load (`loads`, LoadType `course`) holds block sections as class records (key `code|block|semester|year`, LoadType `class`, ParentLoadKey), with or without a class list. The import reads the block from the subject code (`utils/blockSections.ts`: IT 101 A is block A; an unprinted code takes the next free letter in schedule order; forms print no AM/PM, so 1:00-6:59 is afternoon) and `assign_course_batch` saves it. Dean `block.add` (`dean_block_section`) adds a block and registers its class list as the assigned instructor (JWT claims switched for `register_instructor_class`), which now mirrors `Students` onto each block. Dean views read `courseAssignments().sections` (instructor course cards open `DeanCourseInspection`: syllabus, blocks and students with irregular ones tagged, weekly outline); the instructor's block cards show `course.slots` and preset the delivery editor (hideable). Migration `20261118090000_course_load_block_sections.sql` backfills blocks from retained rows when run as postgres.
- **Stale tabs:** a deploy replaces the hashed files, and `vercel.json` answers a missing `/assets/*` with index.html and status 200, so an old tab fails with "Failed to fetch dynamically imported module". `lib/staleBuild.ts` (installed in `main.jsx`) turns Vite's `vite:preloadError` into a "reload" message and one banner; it does not auto-reload, to keep unsaved work.
- **Pulse panel and voice:** header = session dropdown (`PulseSessions.jsx`, search recent chats), Pulse options (rename through the `rename` conversation operation, copy, archive, delete, then page tools) and New chat; composer = + attach menu (files or a picture), mic drop-up (`usePulseVoice` mode `dictate` is long listening sent on Stop; `conversation` uses the VAD, stop phrases and spoken summaries in `voiceConversation.ts`, never confirms record changes by voice) and the provider/model chip (`PulseModelPicker.jsx`, same `providers` API as Settings). `agents/requestGoal.ts` sets each request's goal and progress label; an explicit Internet search (`explicitWebRequest`, `webTopic` in `systemChatPolicy.ts`) skips System Search and answers from the web without a "not found in the system" preamble; an empty System Search answer offers `pagesForTopic` pages. Files go with one message only (a later message reuses them only when it names them, `followUp.ts` `refersToEarlierFile`); a short yes/no answers the latest offer (`lastOffer`: a card to review, "Did you mean", or a closing "Would you like me to …?") and never confirms records; opening another account view (`pulse.viewChange()` from AuthContext) parks the open conversation (`pulseContinuity.ts`) and the remounted Pulse resumes it on the same thread, with view-bound cards turned into notes. "actions" messages render only their cards, not `text`.
- **One place per section (2026-11-22):** within a role no page repeats another page's sections, and the Dashboard never previews or links to other pages. Dean/Program Coordinator Dashboard = oversight (`AcademicManagement` view `monitor` + recent activity; `/monitor` redirects there, preview uses `deanPreview()`); instructor Dashboard = recent course activity (`InstructorOverview`); student Dashboard = reminders, upcoming, block, sources.
