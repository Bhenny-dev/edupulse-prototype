## Authorized reload restoration, 10 November 2026

`AuthContext` keeps `ProtectedRoute` gated through bootstrap instead of publishing the base admin early and redirecting an academic URL to Dashboard. The Supabase callback remains synchronous; deferred restoration first calls `supabase.auth.getUser(accessToken)` and then, when a saved person is selected, `GET /api/ai?action=support&subject=<uuid>`. Each stage has a 20-second client deadline, and generation/abort guards ignore late responses after logout or another session transition. The read-only GET returns the currently authorized subject DTO through the existing live owner/target checks. It does not replay an account-enter/leave operation. A returned ID or role that differs from the saved reference is rejected. The approach follows Supabase's [verified user lookup](https://supabase.com/docs/reference/javascript/auth-getuser) and [auth event subscription](https://supabase.com/docs/reference/javascript/auth-onauthstatechange) contracts.

The tab-local `edupulse-admin-view-v1` hint contains only `{accountId, role, subjectId}`; `subjectId: null` retains an explicit own-account role view. The separate `edupulse-admin-picker-v1` contains only `{accountId, role}` and reopens an unfinished account picker after fresh authorization, with new account results and no saved search or selection command. Both helpers allow only the four academic roles and bind their references to the verified owner. Fresh DTOs supply displayed identity and effective permissions; storage never supplies authority, names, account credentials or provider keys. Token refreshes for an already verified unchanged actor preserve the current view. Role/actor changes invalidate pending restoration and selection responses. Close/select/logout and explicit exits clear the corresponding hints.

Workspace initial reads, autosave and confirmed commits, academic startup and AI connection checks wait for the authentication gate. A timeout, network failure, unavailable subject or changed subject role keeps the requested URL and displays **Could not restore your view**, with **Retry restoring view**. **Return to System Admin** is available only after fresh actor verification; otherwise recovery offers sign-out. No subject page or academic/workspace startup is released while verification remains unresolved. Per-request authorization and the existing RLS boundaries still apply after restoration.

`workspaceViewState` persists a bounded allowlist of navigation references in session storage under the workspace account/support-subject and role. These cover supported course/week/reader selections, source panels, presentation mode/slide and shared layout overlays; existing URL parameters retain page tabs. Content is re-resolved against the currently authorized records. Response caches, editor contents, private result objects and business-command payloads are excluded. Navigation hints do not open a material on the student's behalf, start/respond/submit an assessment, publish, issue a workspace save or run inference. Existing dirty-journal reconciliation and debounce saves retain their revision/conflict rules after authorization. Pending generation checkpoints still require explicit resume.

This extends the earlier deliberate-refresh behavior below: it does not add timer, focus or reconnect polling. Helper and controlled browser fixtures cover references, protected URLs, delayed/failed resolution, explicit exit and pending account pickers; they do not establish production deployment or hosted authentication. See [Manual 23](../system-manual/23-account-support-and-pulse-context/README.md), [Manual 27](../system-manual/27-cached-workspaces/README.md) and [ADR-002](decisions/002-feature-preservation-baseline.md).

## API: one endpoint, eighteen actions

All requests go to `/api/ai?action=<name>`. Every request is checked for origin (same-origin only), size (per-action body limits) and identity; AI actions are limited to **20 requests per minute and one at a time** per user and connection.

Request intake (`server/node-adapter.ts`, shared by the local server and the Vercel function) is bounded before authentication or model work starts: a body that stops arriving receives `408 REQUEST_TIMEOUT` after 30 seconds, a declared or streamed oversize body `413 BODY_TOO_LARGE`, a method the action does not accept `405` with an `Allow` header, and an unknown action (including inherited object-property names) `404`. Node and Fetch handlers read the same action/method table. A client that disconnects aborts the signal passed to downstream work, and an unexpected transport or handler failure returns structured JSON with a request ID and `Cache-Control: no-store`, never the exception text. The intake deadline does not extend the hosted function's duration limit or the model budget.

| --- | --- | --- | --- |

### Pulse tools and context (25 October 2026)

`src/agents/skills.ts` declares the supported tools and schemas. `toolPlanner.ts` validates model proposals for both provider and on-device execution; `server/domains/operator.ts` supplies the authenticated provider transport. Familiar navigation and file intents retain deterministic routing. Editor adapters register an instance and exact snapshot; a stale or unmounted target cannot be modified. Allowed fields exclude course identity, fixed curriculum description, approval, publication, role and enrollment permissions. Unknown fields, invalid URLs and duplicate outline weeks fail validation. Files and prior messages are untrusted source data.

Confirmed mutations use `WorkspaceContext.commit` and the existing revision-checked workspace API. It waits for the persisted response, reconciles a lost response by reading the exact next revision, and preserves later local edits. JSON comparisons ignore object-key ordering while preserving array order and values. Week generation preserves reviewed/published items and rejects a changed syllabus or draft. Model replies cannot assert completion; receipts describe form-only, preview-device or verified database saves.

`server/domains/conversations.ts` stores private chat text and attachment names, not raw uploaded files, executable action payloads or credentials. Explicit recall searches the caller's indexed transcripts and returns source IDs, roles and dates. User response preferences are extracted conservatively from user statements; files/model text cannot create memory. Owner RLS, cascade deletion and quotas are described in [Supabase](supabase.md). Writer prompts contain at most 12 recent turns and 30,000 total characters including instructions; older history is retrieved separately. Operator targets retain complete selected arrays; over-budget edits are rejected instead of silently truncating replacements. On-device planning applies a 6,000-character input limit.

Provider settings and pipeline status share `AIContext` health; outdated requests cannot overwrite a newer refresh. Saved credentials display a fixed masked indicator without exposing the secret. Failed replacements retain editable input and preserve the existing account connection. Model refresh preserves an available selected model; first-time OpenAI selection prefers an available small modern model instead of alphabetically defaulting to GPT-3.5. Discovery excludes announced expired OpenAI models and specialized audio/image/search models.

Modern OpenAI models use `/v1/responses` with `max_output_tokens`, `store: false` and output-message text parsing; legacy GPT-3.5/GPT-4 chat models use Chat Completions with `max_tokens`. JSON drafts request JSON-object output and still pass the courseware schema checks. Other providers keep their fixed, provider-specific endpoints. [OpenAI's text-generation guide](https://developers.openai.com/api/docs/guides/text) describes the Responses protocol.

**Reasoning models and output budgets.** Callers pass budgets for the visible answer: 800 tokens for a general chat reply, 1,600 for other chat, 1,800 for a Pulse tool plan, 5,000 for a revision or JSON draft, 2,400 per bounded courseware part, 2,048 for the connection test and 1,200 for web findings. A model that reasons before it answers spends hidden reasoning tokens from the same output limit ([OpenRouter](https://openrouter.ai/docs/use-cases/reasoning-tokens), [Gemini](https://ai.google.dev/gemini-api/docs/thinking)). With the bare answer budget, the reasoning could use it all: the reply came back empty with `finish_reason: "length"` and was reported as reaching the output limit, even for a short first request. `server/reasoning.ts` adds an allowance of half the answer budget, between 1,024 and 2,048 tokens:

| Provider | Request | If the reasoning still uses the limit |
| --- | --- | --- |
| OpenRouter, model reasons by default or always | `max_tokens` is the answer budget plus the allowance; `reasoning.max_tokens` is the allowance, with `exclude: true` so the reasoning text is not returned | Asked once more with `reasoning.effort: "none"` and the answer budget. A model that must reason, or rejects that request, reports the reasoning limit |
| OpenRouter, model reasons only when asked, or not at all | `max_tokens` is the answer budget | Not applicable |
| OpenAI Responses (GPT-5, o-series) | `max_output_tokens` is the answer budget plus the allowance | Reports the reasoning limit; no retry at the account owner's cost |
| Gemini | `maxOutputTokens` is the answer budget plus the allowance; 2.5 models think by default | The empty reply is reported as before |
| Anthropic, legacy OpenAI chat models | The answer budget; these reason only when asked, and EduPulse does not ask | Not applicable |

The reasoning limit is `INCOMPLETE_RESPONSE` with the message *The model spent its output limit on hidden reasoning before it wrote an answer*. A reply is treated as stopped by its reasoning when it ends at the limit with no answer text, or with more reasoning tokens than the allowance (an effort level can overrun a token cap). An answer that is itself too long keeps the existing output-limit message and is not retried. How each OpenRouter model reasons comes from the public [model catalogue](https://openrouter.ai/api/v1/models) (`supported_parameters` and `reasoning.mandatory` / `reasoning.default_enabled`). It is recorded whenever `discoverModels` lists OpenRouter models, and otherwise read at most hourly, or five minutes after a failed read. A model the catalogue does not list is treated as reasoning: the cap costs nothing for a model that does not reason. Web research applies the same rules to its OpenRouter and OpenAI requests.

**JSON replies.** Not every model has a JSON mode. `cohere/north-mini-code:free`, for example, does not list `response_format` among its supported parameters, so its replies can wrap the JSON in a sentence or a code fence. `parseModelJson` (`src/agents/skills.ts`) reads Pulse tool plans, draft stages and courseware drafts: bare JSON first, otherwise the largest complete top-level object in the reply. It repairs nothing, and the schema checks still decide whether the content is usable.

Catalog health is explicitly distinct from successful inference. `provider-test` accepts only an empty object and probes the saved model with a fixed short prompt and a 2,048-token answer ceiling (reasoning models get their allowance on top), under the existing identity/origin/time/rate limits. A successful text response sets `testedAt` in the encrypted connection cookie. Successful generated chat/courseware also records inference. Selecting another model or replacing a key clears verification; refreshing the same credential/model preserves it. Model-access, incompatible-request, authentication, credit/quota and empty-output errors clear verification while retaining the credential. Error responses expose bounded categories, never raw provider bodies. The Writer propagates these actionable errors even with retrieved evidence; unrelated provider failures can still fall back to source excerpts.

`server/domains/providerOAuth.ts` implements OpenRouter's fixed-host S256 flow. The random verifier/state are sealed in a ten-minute HttpOnly cookie using authenticated encryption. Completion requires the same verified EduPulse owner, origin, unexpired state and PKCE verifier; provider codes are one-use. The dedicated SPA return address `/auth/provider/openrouter` is detected before Supabase initialization, so an external provider code is not consumed as an EduPulse sign-in code. Legacy query-marker returns remain supported; a short-lived state-only session-storage marker also recognizes a return with a stripped query marker. The dedicated path does not depend on browser storage. The UI waits for EduPulse authentication to settle, removes callback parameters and opens AI settings, or shows session-recovery guidance.

The server returns only public connection metadata. Failed code exchanges preserve the previous connection. After a verified exchange, a model-catalog outage saves the newly authorized credential with no selected model, so **Refresh models** can finish setup without exchanging a consumed code again. Existing hosted account leases also bound these commands. No OAuth password, key or token is written to local/session storage or returned in JSON; the optional browser marker contains only state and expiry.

OpenRouter authorization is available; direct hosted ChatGPT sign-in requires provider approval that this project does not currently have. Claude API connections support scoped keys and an explicit `workspaceId` for unscoped personal/service keys. The selected ID is sealed with the account-bound credential and sent as `anthropic-workspace-id` to Models and Messages. `provider-workspaces` performs read-only, paginated discovery against Anthropic with `include_default=true`; it accepts the entered key or the caller's saved Anthropic key, never a hosted/server key. Only workspace IDs and names are returned. If listing is forbidden, the form accepts an ID copied from Claude Console without requesting broader permissions. No workspace is selected automatically. Changing it clears generation verification. [Anthropic authentication](https://platform.claude.com/docs/en/manage-claude/authentication) defines workspace selection; [List Workspaces](https://platform.claude.com/docs/en/api/organization/workspaces/list) defines discovery. The [manual](../system-manual/08-ai-connections/README.md) documents provider capabilities and the distinction between synthetic authorization regressions and live consent. Callback exchange failures remain visible as alerts even without a saved connection; starting another settings operation clears stale callback notices.

The system admin dashboard calls the gated `edupulse_admin_overview` database RPC for account coverage and recent activity. The separate `admin-accounts` Supabase Edge Function creates role accounts and assigns roles after verifying the live Google admin identity. The admin view also checks authentication, Google sign-in, the audit query and the Pulse API. Each account connects its own AI provider in Settings; a role switch never shares an AI key or another user's workspace.

## The agent graph

Built with LangGraph (`src/lib/rag/agents.ts`); the same graph runs on the server and, for the on-device model, in the browser.

| Agent | Role |
| --- | --- |
| **Guardian** | Checks appropriate use before any other agent works (`src/lib/rag/policy.ts`). It declines learners’ requests for assessment answers, excluded features (plagiarism or AI-authorship detection, integrity scoring, at-risk prediction, proctoring) and official grade computation, and cites the rule it enforces. The rules are deterministic and run before any model. |
| **Planner** | Classifies the request (answer, compare, references, draft) and splits it into focused search queries |
| **Researcher** (one per query, in parallel) | Hybrid search: pgvector cosine + Postgres full-text, fused with reciprocal rank fusion |
| **Ranker** | Cross-encoder reranking, relevance floor, near-duplicate removal, at most three passages per document; for comparisons both documents must contribute and reference-list passages are skipped |
| **Comparator** | Aligns statements from two documents (shared, related, only-in-one) and reports coverage; never judges authorship |
| **Writer** | Generates the answer with numbered citations, using only the ranked passages |
| **Verifier** | Checks every sentence against its cited passage (0.55 × semantic + 0.45 × lexical support) with consistency gates for numbers, names and absolute words; counts corroborating documents |
| **Corrector** | Fixes wrong or missing citation numbers deterministically, asks the Writer for one revision if statements are unsupported, and falls back to quoting sources |
| **Librarian** | Finds real references in Open Library, OpenAlex and Wikipedia (allowlisted, no key) |

Every step is returned to the interface as the *How Pulse worked on this* timeline.

**Agent registry and tracking.** `src/lib/rag/registry.ts` holds each agent’s job title, task and measurable goal, and judges after every run whether each agent met its goal. The API records each signed-in hosted run in `edupulse_agent_runs` (`server/agentRuns.ts`): workflow, task, outcome, rule, provider and model, duration, counts, and per-agent goal results named after the OpenTelemetry GenAI agent conventions (`gen_ai.operation.name` = `invoke_agent`, `gen_ai.agent.name`). ## Document ingestion pipeline

`upload → type sniffing → sandboxed extraction → quality report → (OCR of scanned pages, on the device) → human review → split → embed → store`

* **Sandbox:** each file is parsed in a separate worker thread with a 256 MB heap, a 30-second limit, an empty environment (no secrets) and at most two at a time. If the worker cannot start, the upload fails; untrusted files are never parsed in the API process.
* **Checks before parsing:** the real file type must match the name; Office files are inspected through the ZIP central directory and refused if they would expand to an unsafe size; legacy and password-protected formats are refused with a reason.
* **Excel workbooks (`.xlsx`):** read in the same sandbox with the same ZIP checks. Each visible sheet becomes a `## Sheet name` heading followed by comma-separated rows of the values Excel last saved; formulas are never evaluated, hidden sheets are skipped, and a workbook is limited to 20 visible sheets and 5,000 rows. An indexed workbook is stored with source type `csv`, which the database's existing `source_type` check accepts.
* **OCR for scanned PDFs:** runs in the browser, never on the server. A PDF with no text layer is refused by the sandbox with code `NO_READABLE_TEXT`; for it, and for PDF pages with fewer than 20 characters of text, the Knowledge library offers OCR. PDF.js (the eval-free build the sandbox uses) renders each such page at about 300 dpi, and Tesseract 7 (English LSTM model, `4.0.0_best_int`) reads it in a Web Worker. Page images never leave the device. The text is placed under its `[[Page n]]` marker, then sent as plain text through the same sandboxed cleaning, quality and instruction checks, and the instructor reviews it before indexing. Up to 60 scanned pages per run; pages below 70% confidence and pages with no text are named in the review.
* **Prompt-injection defence:** instruction-like text is flagged in the review and neutralised before it reaches a model; the model is told that document text is data.
* **Splitting and embedding:** LangChain recursive splitter; all-MiniLM-L6-v2 (384-d, int8 ONNX) embeddings; pages and slides are kept so answers can cite them.

## Security summary

* Provider keys and the Supabase secret never reach the browser. Personal provider keys are encrypted with AES-256-GCM (`AI_CONNECTION_SECRET`) into a `__Host-` cookie that expires within seven days.
