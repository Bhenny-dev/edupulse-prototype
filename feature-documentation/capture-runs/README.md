# Capture execution evidence

The snapshot reporter writes one JSON report per actual Playwright invocation, plus `latest.json`. Every selected suite uses the shared page/CSP error fixture, including mobile, manual tasks, uploads and conversation. Reports include executed test status/counts, unselected suites, browser/viewport, build mode, source commit and content digest, and the hash of each screenshot written during that invocation. A partial run does not certify suites listed as unselected.

Run `npm run build:capture` before Playwright. The build records its source digest in `dist-capture/capture-build.json`; it includes application source and the capture pipeline, normalizing text line endings across Windows/CI. Stale builds and source changes during capture are rejected. Locale/timezone are fixed to `en-US` / `Asia/Manila`. `SNAPSHOT_SCENES` can select walkthrough scenes with a regular expression; the filter is recorded in execution metadata. A selected run merges those scenes into the existing desktop manifest; a complete unfiltered walkthrough replaces it. Remove obsolete scene entries and images when removing a screen.

`image-review.json` records visual inspection of the exact image hashes. Record the reviewer and review time only after opening each image. An agent review must identify itself as an agent; this record is an attestation, not automatic proof of human review. The documentation gate rejects changed screenshots without matching successful execution and review evidence. Image hashes support provenance; they do not prove backend persistence or accessibility.

Preview/sample rosters and scores, real local extraction/model tasks, synthetic provider transports, and authenticated hosted checks are different evidence categories. Each task guide describes its fixtures. Local reports mark production checks as not run; hosted account captures record deployment origin/SHA and their actual synthetic-account result. `SNAPSHOT_PROTECTION_STORAGE` can load an ignored browser cookie state for an authenticated protected deployment. Credentials and share links never enter reports. Historical `capture-manifest.json` and `capture-log.json` remain for compatibility. They do not replace this per-invocation record, and a new partial run does not retroactively validate old captures.
