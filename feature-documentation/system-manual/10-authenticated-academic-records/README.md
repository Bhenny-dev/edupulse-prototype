# 10 · Use authenticated academic records

**Who:** instructors, enrolled students, Dean and Associate Dean. Requirements FR-AUTH-10/11, FR-PERF-13, FR-CW-04. Evidence IDs: `AUTH-001`, `DATA-001`, `CW-001`.

1. Sign in with the assigned account. Preview personas continue to demonstrate sample screens; authenticated academic views never substitute those fixtures. An empty account shows **No authorized academic records yet**.
2. As instructor, register the confirmed EduSuite class list in **Student Monitoring → Students**, using the student's verified account email. Activate the approved syllabus through the existing offline lifecycle. Clean legacy instructor workspaces synchronize automatically after loading.
3. Generate or author courseware, review it and mark it **Checked**. Wait for the workspace to save, then choose **Publish**. A direct unreviewed publication, a changed checked payload, or a publication without an active approved syllabus is rejected. Drafts and answer keys are not student-readable.
4. As enrolled student, open **My Courses**, then **Open material**. The opening is stored against the signed-in identity. Open **Assessments**, choose **Open assessment**, answer every item and press **Confirm and submit responses**. The server validates enrollment, publication version and responses, computes raw objective points, and saves one attempt. Retrying returns the saved result.
5. **Performance** shows the student's own results. Restored account tabs include assessment radar/history, matrices, materials, scores, filters and CSV; topic mapping gaps are explicit. The instructor's **Student Monitoring** shows results for owned classes. Dean gets read-only college results. Associate Dean gets course/delivery/roster oversight, with no score access. Neither changing a URL nor forging a client role grants permission. See the [restored section steps](../13-restored-account-sections/README.md).
6. Authorized server data loads on account/view entry and reads back confirmed mutations. Focus, timers and reconnects retain the loaded view; use explicit Refresh or Retry to load newer records. **Export authorized records** downloads the same authorized projection as JSON, including recorded results where permitted. If the connection fails, an error is shown; fixtures do not replace missing records. **Settings → Data & Privacy → Export workspace backup** retains the instructor's original workspace snapshot separately.

The [authenticated walkthrough](../../system-walkthrough/08-authenticated-records/README.md) shows each role with synthetic hosted canaries. `tests/snapshots/authenticated.spec.ts` exercises actual sign-in and UI reads; `scripts/academic-canary.ts` checks the API/account pairs and duplicate submissions; `tests/academic.test.ts` checks the migration, direct RLS access, private answer keys and distributed account leases. These are controlled tests, separate from a live institution's academic results.

Current walkthrough images use synthetic UI transport to keep the screen layout current. They do not re-run hosted account/RLS checks. Record loading shows skeleton cards and table rows; failed loads show an error and **Retry connection** rather than claiming the account is empty. Short requests show a spinner. See [loading feedback](../12-interface-and-loading/README.md).

## Instructor monitoring update

The instructor now chooses a year-level course/block card before viewing Students, Assessment Scores or Learning Material Access. The separate instructor Performance page redirects here. Student and Dean views retain their roles. [Manual 37](../37-instructor-monitoring/README.md) supersedes the earlier instructor screenshots and distinguishes recorded first opens from sequential section confirmations.

Assigned courses can appear before content release, with units/year/period and a pending notice. The separate metadata RPC exposes only the current student's assignment labels, never a draft outline or source bytes. [Manual 38](../38-curriculum-population/README.md).
