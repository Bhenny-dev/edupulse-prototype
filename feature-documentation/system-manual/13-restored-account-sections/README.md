# Use the restored account sections

The [role guide](../../system-walkthrough/09-restored-role-pages/README.md) uses synthetic account/API/workspace captures. They demonstrate the interface, not production authentication or institutional results. Shared workflows require the four migrations in the [baseline release record](../../versions/2026-10-28-baseline-workflows/README.md); they were applied to EduPulse System on 28 October 2026.

1. Open **Dashboard** and use your role's **Quick actions**. Instructor **Getting started with EduPulse** reflects saved syllabus, activation, courseware and class-list state. The review queue and lifecycle use the owner workspace. Management sees faculty, syllabus stations, planned/published week coverage, readiness and recent saved activity. Students see blocks, material sources, upcoming recorded deadlines, unread/unanswered work and mapped topic results.
2. In **Performance**, choose **Course**, **Block**, **From** and **Through** where available. **Overview** retains raw assessment charts. **By Topic** shows a separate syllabus-topic radar, history, status, instructor heatmap and class charts. Only mapped, graded responses contribute; at least three assessed topics are needed for a radar. **Not assessed** is distinct from zero. The latest attempt per publication version contributes to current mastery. The **Alerts** cutoff filters score/topic alerts; **Acknowledge topic alert** saves a private acknowledgment for that result/cutoff.
3. In **Student Monitoring → Assessment Scores**, inspect the score matrix and saved attempts. In **Review responses and score adjustments**, choose **Assessment attempt**, read the answers, set each question's 0/1 mark, enter **Review reason**, then **Confirm reviewed marks**. Written responses remain **Awaiting instructor marking** until reviewed. The student receives an in-app notice. Dean can read results but cannot mark them; Associate Dean cannot enter Performance or read scores.
4. In **Remind about missing work**, choose a publication and press **Confirm reminder**. A saved notice goes to provisioned enrolled students without a current attempt/material open. The command excludes reminders already sent for that item within one day. This is in-app delivery, not email. A material open does not prove completed reading.
5. Dean/Associate Dean open **Records → File Import**. Import **Course Records**, then **Course Loads**, then **Student Class Lists**, using **Templates** for headers. Preview valid/rejected rows and **Confirm Import**. CSV is limited to 1 MB and 1,000 rows per request. Confirmation updates shared college records. Loads require a provisioned instructor account ID and imported course; rosters link by block and verified account email. **History** records confirmed imports. Earlier private intake stays in the owner backup and can be downloaded for explicit re-import.
6. In **Records → Blocks / Sections**, choose an **Imported student**, enter **Confirmed block** and **Confirm block correction**. The backend enforces at most 35 active imported students per block. Matched instructor projections receive enrollment. In **Course Loading → Instructors**, choose course/block/semester and instructor, then **Preview selected load**, **Suggest highest-priority instructor**, or **Auto-propose semester loads**. Qualifications come from confirmed load rows (optional **HasMasters**, **Specialization** columns). Review/override each instructor, then **Confirm … proposed load(s)**. Suggestions follow the degree/specialization rule; they do not write to EduSuite.
7. Management retains four **Monitor** tabs. Dean additionally has **Review Inbox**. Choose **Course to review**, inspect the outline, enter **Correction request**, then **Confirm correction request**. The instructor receives a saved notice. Dean reviews the downloaded file; CAO approval and EVP noting remain offline. No button grants electronic approval.
8. In instructor **Courseware**, open an assessment and assign **Question … syllabus topic** from the approved outline week. Choose multiple choice, fixed True/False choices or instructor-marked written response, then **Save Assessment**. Unmapped questions are excluded from mastery. Each question is worth one point; published assessments contain 3–5 questions. Under **Delivery settings**, set **Release at**, **Due at**, **Time limit (minutes, 0 = none)** and **Allowed attempts** (1–3), then **Save delivery settings**. Changed rules return the item to Draft; review/check again before publishing. A future release stays hidden from students until its saved time. Browser-local times are stored in UTC.
9. Students open **My Courses**, expand a week and **Open material**. Document/presentation/PDF/print controls remain. **Open assessment** starts the server session. Use numbered navigation or Previous/Next to answer one question at a time; answer every question and **Confirm and submit responses**. Duration/deadline are enforced on the server. Retrying a lost submission response returns the saved attempt. Written answers await marking. **Start next allowed attempt** appears only when permitted. Enter **Appeal to instructor** and **Submit appeal** to contest a result.
10. In **Syllabus → My Syllabus → Version History**, inspect recorded stations and up to ten saved editable versions. **View saved version** opens one; **Restore version as draft** creates a new draft, clears approval and flags changed teaching weeks for courseware review. Editing an active syllabus also returns it to the offline route and withdraws publications until reactivation. Approved-file bytes are not duplicated into historical versions.
11. **Notifications → Mark All Read** saves persisted academic notice receipts to the account. Derived reminders also appear with device read state. Refresh/background refresh reloads saved data without discarding an open form. Solid dark mode uses the theme control. **Export authorized records** downloads the projection; **Settings → Data & Privacy → Export workspace backup** downloads the owner workspace.

See the [50 illustrated views](../../system-walkthrough/09-restored-role-pages/README.md) for the current controls and capture provenance.

Account guidance now describes confirmed shared imports/loading, saved topic results and enrolled publication, with role-specific follow-up actions. Preview personas retain sample warnings. Authenticated Records and Course Loading expose their page targets again; Dean guidance cannot mark results and Associate Dean guidance excludes scores. See the [account Pulse capture](../../system-walkthrough/09-restored-role-pages/README.md#pulse-account-guidance).

**Archive** retains the instructor-owned syllabus and courseware records while withdrawing their shared publication visibility. It does not require deleting authored content first. Existing saved syllabi also receive the new station/outline/reference metadata when the first migration is applied; an instructor resave is not required just to populate those restored read views.
