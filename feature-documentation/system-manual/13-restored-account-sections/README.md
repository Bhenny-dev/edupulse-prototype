# Use the restored account sections

The [role guide](../../system-walkthrough/09-restored-role-pages/README.md) uses synthetic account/API/workspace captures. They demonstrate the interface, not production authentication or institutional results. Shared workflows require the four migrations in the [baseline release record](../../versions/2026-10-28-baseline-workflows/README.md); they were applied to EduPulse System on 28 October 2026.

1. Open **Dashboard**. Your account gets the same role dashboard as the preview personas, filled from your own records; sample values never appear. Records load on entry and after confirmed changes; focus, timers and reconnects keep the loaded view, and Refresh loads newer records. The routine ready indicator and header export are removed; updating, offline and error feedback remain. Dashboard entry/reload only reads confirmed records; confirmed saves maintain the projection. Instructors and management start from **Quick actions**. Instructor summary cards, syllabus stations and the review queue use the owner workspace, and a saved syllabus or courseware item completes the first two **Getting Started with EduPulse** steps. **My Block Sections**, **Score Snapshot** and **Recent Activity** use the authorized records; averages include only learners with marked attempts. Management sees course counts, syllabus stations, published delivery, faculty, recent saved activity and syllabus status by course. Students see reminders for unopened materials and unanswered assessments, their block, each course's latest marked score, material sources, their score trend and recorded deadlines.
2. Students and Dean retain **Performance** with course/block/date filters where authorized. Instructors open **Student Monitoring**, select a course/block card under its year level, then **Assessment Scores**. Summaries, assessment radar/history, class averages, submission rates and student breakdowns share that exact roster. Expand **Topic mastery and follow-up** for mapped topic radar/history/status, the class heatmap, cutoff review, acknowledgments and historical attempts. Only mapped, graded responses contribute; at least three assessed topics are needed for a topic radar. Missing or unmarked results remain distinct from zero. [Manual 37](../37-instructor-monitoring/README.md) describes the combined class workflow.
3. In **Student Monitoring → selected course/block → Assessment Scores**, inspect the student score list and saved attempts. In **Review responses and score adjustments**, choose **Assessment attempt**, read the answers, set each question's 0/1 mark, enter **Review reason**, then **Confirm reviewed marks**. Written responses remain **Awaiting instructor marking** until reviewed. The student receives an in-app notice. Dean can read results but cannot mark them; Program Coordinator cannot enter Performance or read scores.
4. In **Remind about missing work**, choose a publication and press **Confirm reminder**. A saved notice goes to provisioned enrolled students without a current attempt/material open. The command excludes reminders already sent for that item within one day. This is in-app delivery, not email. A material open does not prove completed reading.
5. Program Coordinators open **Records → File Import**. Import **Course Records**, then **Course Loads**, then **Student Class Lists**, using **Templates** for headers. Preview valid/rejected rows and **Confirm Import**. CSV is limited to 1 MB and 1,000 rows per request. Confirmation updates shared college records. Loads require a provisioned instructor account ID and imported course; rosters link by block and verified account email. **History** records confirmed imports. Earlier private intake stays in the owner backup and can be downloaded for explicit re-import.
6. As Program Coordinator, in **Records → Blocks / Sections**, choose an **Imported student**, enter **Confirmed block** and **Confirm block correction**. The backend enforces at most 35 active imported students per block. Matched instructor projections receive enrollment. In **Course Loading → Instructors**, choose course/block/semester and instructor, then **Preview selected load**, **Suggest highest-priority instructor**, or **Auto-propose semester loads**. Qualifications come from confirmed load rows (optional **HasMasters**, **Specialization** columns). Review/override each instructor, then **Confirm … proposed load(s)**. Suggestions follow the degree/specialization rule; they do not write to EduSuite.
7. Dean and Program Coordinator oversight retains **Syllabus & Delivery**, **Student Oversight** and **Alerts**. Review and approval take place outside EduPulse; no review inbox or correction-request form is available.
8. In instructor **Course**, open an assessment and assign **Question … syllabus topic** from the approved outline week. Choose multiple choice, fixed True/False choices or instructor-marked written response, then **Save Assessment**. Unmapped questions are excluded from mastery. Each question is worth one point; published assessments contain 3–5 questions. Under **Delivery settings**, set **Release at**, **Due at**, **Time limit (minutes, 0 = none)** and **Allowed attempts** (1–3), then **Save delivery settings**. Changed rules return the item to Draft; review/check again before publishing. A future release stays hidden from students until its saved time. Browser-local times are stored in UTC.
9. Students open **My Courses**, expand a week and **Open material**. Document/presentation/PDF/print controls remain. In the full Document reader, confirm sections in order to save version-bound reading progress; an open alone never completes reading. **Open assessment** starts the server session. Use numbered navigation or Previous/Next to answer one question at a time; answer every question and **Confirm and submit responses**. Duration/deadline are enforced on the server. Retrying a lost submission response returns the saved attempt. Written answers await marking. **Start next allowed attempt** appears only when permitted. Enter **Appeal to instructor** and **Submit appeal** to contest a result.
10. In **Syllabus > My Syllabus**, open the current syllabus reader. Version History, saved-version viewing/restoration and Copy for next term controls are removed. Existing revisions remain stored internally. Use **Suspend syllabus** before the separate **Delete syllabus** action; see [the current sharing and suspension guide](../36-instructor-syllabi/README.md). Editing an active syllabus still withdraws publications until reactivation.
11. **Notifications → Mark All Read** saves persisted academic notice receipts to the account. Derived reminders also appear with device read state. Manual refresh reloads saved data; focus, timers and reconnects do not involuntarily reload loaded pages. Solid dark mode uses the theme control. **Settings → Data & Privacy → Export workspace backup** downloads the owner workspace.

See the [50 illustrated views](../../system-walkthrough/09-restored-role-pages/README.md) for the current controls and capture provenance.

Account guidance now describes confirmed shared imports/loading, saved topic results and enrolled publication, with role-specific follow-up actions. Preview personas retain sample warnings. Authenticated Records and Course Loading expose their page targets again; Dean guidance cannot mark results and Program Coordinator guidance excludes scores. See the [account Pulse capture](../../system-walkthrough/09-restored-role-pages/README.md#pulse-account-guidance).

**Delete syllabus** replaces Archive under the later owner correction. It appears only after a separate saved suspension and requires confirmation. It removes the owned syllabus and its workspace courseware, withdraws publications and retains scored history. Sharing, received-copy adoption and saved suspension before deletion are described in [Manual 36](../36-instructor-syllabi/README.md). Existing saved syllabi also receive the new station/outline/reference metadata when the first migration is applied; an instructor resave is not required just to populate those restored read views.

[Manual 21](../21-automatic-records-and-course-rosters/README.md) covers automatic recovery and the instructor's **Student Monitoring → Students** roster tools.

Admin support can now load a selected person's academic view under that account's permissions. Learner support previews do not record material access or permit assessment submissions or appeals; use the learner's own sign-in for actual activity. [Manual 23](../23-account-support-and-pulse-context/README.md) documents the account picker and the hosted delivery check.

## Combined syllabus and delivery oversight

[Manual 29](../29-combined-oversight/README.md) replaces the duplicate top-level syllabus/delivery tabs with one combined view. Saved stations, released material/assessment charts, coverage, CSV, course details, class lists, Student Oversight, Alerts remain; review and approval take place outside EduPulse. Teaching-week coverage excludes future and unplanned/examination weeks; it never certifies completion or lateness.

## Dean activity pages

The Dean now uses **Course**, **Instructors** and **Students** for read-only course, load, roster and activity records. File Import, Templates, History and block-edit forms remain Program Coordinator workflows. Year-grouped block cards open searchable, downloadable student dialogs. Dashboard and page summaries share one clickable design. Old Dean loading/sections links resolve to the new pages. See [Manual 36](../36-dean-activity-records/README.md).

## Current authenticated student learning

[Manual 41](../41-student-learning/README.md) supersedes the earlier flat courseware and assessment list instructions: My Courses has instructor-labelled enrollment cards, and Practice Assessments has separate repeatable self-practice and instructor baselines. Material reading no longer waits for its first-open receipt. The verified Admin can use labelled student actions directly, without a separate demonstration checkbox. Performance keeps raw assessment and material-access history.
