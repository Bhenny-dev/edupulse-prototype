# Approved syllabus file compatibility — 9 November 2026

The owner's supplied approved PDFs exposed an intake mismatch: several exceed the previous 500 KB retained-file limit, and their tables use scaled graphics, split labels, partial borders and page-spanning rows. The reader now handles those structures and both client/server approved-file limits use 750 KB. The total workspace limit remains 3 MB.

Readable course fields take precedence over stale catalog or footer text. The builder also keeps an imported code outside its catalog visible in the selector and retains the source title/year. Worded and numeric printed week ranges stay explicit; bottom-of-page row fragments join a compatible first row on the next page where its week is printed. Genuinely unnumbered rows remain review warnings instead of examination content or invented weeks. Empty boilerplate and list markers do not become lessons.

The direct intake uses a shared pure candidate builder for the same validation in the interface and authorized intake tooling. It does not save or attest approval by itself. Existing direct approved-copy intake, optional drafting, explicit confirmation, immutable original bytes/checksum, save revisions, ownership, review/publication and student activity boundaries remain.

[Manual 30](../../system-manual/30-approved-syllabus-intake/README.md) documents the preview. [Validation](validation/results.md) separates genuine local scanning of the 14 owner files from synthetic account UI captures and pending hosted seeding. This release adds no migration or account mutation.
