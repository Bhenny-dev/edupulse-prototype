# Targeted syllabus editing ? 12 November 2026

The reported request reached a whole-array replacement contract rather than a section update. This release resolves the exact target from the mounted editor before inference, accepts content-only edits, and merges them into the unchanged baseline. It keeps shared IDs and all existing calendar associations. See [the user guide](../../system-manual/38-targeted-outline-edits/README.md) and [validation](validation/results.md).

## Investigation

1. `workTools.sectionFor` interpreted bare ?Section 2? as Course Description even when the request named Week 1. Week-qualified instructions now take outline precedence.
2. `Pulse.prepareEdit` supplies the editor baseline, request and selected field. It now sends the bound field path explicitly. `requestOperator` chooses the connected provider or browser runtime. Both call `planValidatedTool` and `draftHarness`; target resolution and validation are shared code, independent of billing/authentication mode.
3. The old `toolPlanner` prompt listed `courseOutline:[{week,ilos,contents,...}]` without nested sections, while `draftHarness` instructed the model to retain section IDs. Its example also omitted sections. The model could therefore return aggregate week values or only the requested section. `validateDraft` then correctly rejected omitted protected IDs: ?retain every existing section ID in week 1.? The safety check exposed the contract mismatch; persistence was not the cause.
4. The older contract replaced the entire array. Omitting nested sections also allowed later `normalizeOutlineSections/weekSections` to create a default `week-N` canonical section in some legacy single-section paths. Targeted editing now bypasses that model replacement path entirely. Whole-outline stages with existing nested sections also use content-only targets. The replacement validator additionally rejects new/duplicate IDs and inconsistent shared content.
5. IDs are currently stored inside each syllabus's JSON outline in the workspace, not a separate database-generated section table. New manual sections use a UUID; imported/legacy sections can have stable derived IDs. Every existing persisted identifier is retained exactly by the targeted contract, regardless of origin.

## Editing contract and save boundary

`outlineEdits.resolveOutlineEdit` maps explicit week/section positions or an allowlisted bound field path to existing baseline IDs. Only temporary target ordinals, selected current values, bounded read-only previews of the same section?s other teaching fields, course context and shared week numbers enter the model prompt. The read-only previews preserve topic/outcome context for a single-field change and cannot be returned as writable fields. The strict response is `edits:[{target:1,changes:{activities:"..."}}]`; fields depend on the user's selected scope. IDs, week arrays, relationships, arbitrary paths, unknown fields and duplicate/missing targets are rejected. A list-item target accepts one replacement item. Completion requires nonempty selected fields, without requiring unrelated fields to be complete. Unsupported targets fail before inference.

`mergeOutlineEdits` copies the baseline, applies only allowlisted values by the resolved ID and re-aggregates affected weeks. It preserves sibling contents, resources, examination slots and every shared membership. Shared IDs are updated in all associated weeks. The merged result still passes the existing syllabus/source validation. One repair operates on the same baseline and scope. Invalid attempts never enter the editor.

The existing preview controls require explicit application/save. `applyEditorProposal` compares the entire current editor to its original baseline, rejecting changed-page or concurrent local edits before applying. `Syllabus` saves through `onComplete` and the workspace store. `workspaceInput` validates before any write; `saveWorkspace` now repeats this validation at the service boundary for internal callers and returns field paths for invalid shared sections. The existing owner-scoped local conditional update or hosted `edupulse_save_workspace` RPC commits the complete validated snapshot with an expected revision in one atomic operation. No per-section writes, partial SQL commits or weakened integrity checks were introduced. Stale retries cannot overwrite a newer revision.

Existing provider adapters and local inference use the same contract. This change does not add a subscription sign-in integration or alter provider billing. Reload restoration remains the existing authorized route/support-subject mechanism; no generation, application or save is replayed on reload. Unsaved editor data is not stored as navigation hints.
